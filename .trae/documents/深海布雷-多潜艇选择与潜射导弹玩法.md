# 深海布雷 — 多潜艇选择与潜射导弹玩法 实现计划

## 1. 摘要

新增"多潜艇可选"玩法，两种潜艇在开局菜单二选一，整局固定：

1. **柴电潜艇（默认）**：保留现有全部手感与外观，武器只有水雷（弹仓 5 枚、1.6 秒回充）。
2. **核潜艇（建模参考 093A 型攻击核潜艇）**：没有水雷，改为潜射导弹（弹仓 3 枚、5 秒回充）；导弹冲出水面后自动锁定最近敌舰，命中后大范围爆炸（伤害 2、半径 118）。
3. **属性差异化**：核潜艇艇体更长（152 vs 116）、最大速度更低（300 vs 360）、推进更迟钝（2.4 vs 3.2）、受击判定更大（半径 28 vs 18）；生命、维修、关卡、敌舰与计分框架不变。
4. **配套 UI**：菜单新增两张开局选艇卡；HUD 弹仓区根据潜艇切换水雷/导弹样式与文案；结算界面新增"更换潜艇"返回标题。

不改动：水雷现有机制与数值、敌舰行为、关卡编队、生命/维修规则、计分基础值、`file://` 双击运行方式、零外部资源约束。

## 3. 具体改动

### 3.1 `js/config.js` — 潜艇与导弹配置

#### 3.1.1 新增 `CFG.SUBMARINES`

```js
SUBMARINES: {
  diesel: {
    id: 'diesel',
    name: '柴电潜艇',
    model: '039C 型',
    role: 'DIESEL-ELECTRIC',
    weapon: 'mine',
    len: 116,
    speed: 360,
    thrust: 3.2,
    radius: 18
  },
  nuclear: {
    id: 'nuclear',
    name: '核潜艇',
    model: '093A 型',
    role: 'NUCLEAR ATTACK',
    weapon: 'missile',
    len: 152,
    speed: 300,
    thrust: 2.4,
    radius: 28
  }
}
```

数值含义：

| 字段 | 柴电 | 核潜艇 | 作用 |
|---|---|---|---|
| `len` | 116 | 152 | 视觉长度与尾流/气泡位置 |
| `speed` | 360 | 300 | 最大潜航速度（px/s） |
| `thrust` | 3.2 | 2.4 | 推进响应率，越小越迟钝 |
| `radius` | 18 | 28 | 深弹受击判定半径 |

#### 3.1.2 精简 `CFG.PLAYER`

删除 `MAX_SPEED / THRUST / RADIUS / LENGTH`，保留所有两种潜艇共用的字段：

- `LIVES / MAX_LIVES / START_X / START_Y`
- `MIN_X / MAX_X / MIN_Y / MAX_Y`
- `ARRIVE_GAIN / CURRENT_X / CURRENT_Y / CURRENT_PERIOD_X / CURRENT_PERIOD_Y`
- `INVULN`

#### 3.1.3 新增 `CFG.MISSILE`

```js
MISSILE: {
  MAGAZINE: 3,          // 弹仓上限
  RELOAD: 5.0,          // 每枚回充秒数
  FIRE_CD: 0.6,         // 发射间隔
  RISE_SPEED: 430,      // 水下垂直上浮速度
  CRUISE_SPEED: 680,    // 出水后巡航速度
  CRUISE_Y: 56,         // 巡航高度（海面以上）
  LOCK_RANGE: 640,      // 自动锁定最近敌舰的最大水平距离
  BLAST_RADIUS: 118,    // 爆炸半径
  DAMAGE: 2,            // 对舰船伤害
  LOST_CLIMB_SPEED: 300 // 无目标时爬升离场速度
}
```

`CFG.MINE` 原有字段全部保留，继续作为柴电潜艇的武器参数。

### 3.2 `js/entities.js` — 潜艇分型与导弹实体

#### 3.2.1 `Submarine` 构造与移动

构造器改为：

```js
constructor(x, y, kind = 'diesel') {
  this.kind = CFG.SUBMARINES[kind] ? kind : 'diesel';
  this.spec = CFG.SUBMARINES[this.kind];
  this.len = this.spec.len;
  // 其余字段保持不变
}
```

`update(dt)` 中：

- `CFG.PLAYER.MAX_SPEED` → `this.spec.speed`
- `CFG.PLAYER.THRUST` → `this.spec.thrust`
- 螺旋桨气泡位置由固定 `this.x - this.facing * 64` 改为 `this.x - this.facing * (this.spec.len * 0.55)`
  - 柴电：116 × 0.55 ≈ 63.8，与现有 64 基本一致
  - 核潜艇：152 × 0.55 ≈ 83.6，气泡跟随更长的艇尾

`idle(dt)`、洋流、边界、朝向、纵倾、无敌计时逻辑不变。

#### 3.2.2 `Submarine` 绘制分派

把现有 `draw()` 拆成"外壳 + 艇型绘制"两层，保证柴电外观不变：

- `draw(ctx, time)` 外壳：
  1. 存活判断、无敌闪烁、`translate → rotate → scale`
  2. 艇艏探照灯锥：锥体起点改为 `this.spec.len * 0.48`，终点起点 + 174
     - 柴电：55.7 ≈ 现有 56
     - 核潜艇：73，光锥更靠前
  3. `this.drawBody(ctx, time)`：按 `this.kind` 分派到 `drawDieselBody` / `drawNuclearBody`
  4. 用 `this.hullPath(ctx)` 裁剪并绘制受击红闪
  5. `restore` 后绘制无敌护盾环：半径由固定 38 改为 `this.spec.radius + 20`
     - 柴电：38（保持不变）
     - 核潜艇：48
- `hullPath(ctx)` 按 `this.kind` 分派：
  - `diesel`：现有 116 长度水滴形路径，原样保留
  - `nuclear`：新增 152 长度长水滴形路径
- `drawDieselBody`：把现有 `draw()` 中螺旋桨、尾轴、X 尾舵、艇体、声呐罩、消声瓦、侧舷阵列、鱼雷管、围壳、潜望镜、信号灯等代码整体搬入，不改视觉参数。
- `drawNuclearBody`：新增 093A 风格绘制，具体见 3.2.3。

#### 3.2.3 核潜艇（093A）绘制细节

局部坐标仍为"艇艏朝 +x"，整体由外层 `scale(facing, 1)` 镜像。绘制顺序：

1. **七叶螺旋桨**：位于 `x = -74`，整体 `scale(1.22)`，按 `time * 11` 旋转；桨叶用现有七叶后掠曲线放大，中心轴帽更深色。
2. **尾轴与 X 形尾舵**：尾轴从 `-60` 到 `-72`；X 舵位于 `-40 ~ -64`，上下各一对，深色填充 + 青色细描边。
3. **长水滴形艇体**（新 `nuclearHullPath`）：
   - 艇艏最前点 `+74`，中段半高约 `18.5`，艇尾收缩到 `-66`
   - 贝塞尔轮廓比柴电更长、更饱满，中段接近平行圆柱
   - 渐变：顶部 `#4a6a76` → 中段 `#1a3441` → 底部 `#06121a`，保留 1.1px 青色轮廓光
4. **艇艏声呐罩**：`+52 ~ +74` 浅色渐变区，弧线分缝。
5. **顶部高光 + 消声瓦分缝**：沿更长艇体分布 7 条纵向细缝 + 1 条水平缝。
6. **侧舷声呐阵列**：艇体中下部 `-40 ~ +26` 的长条深色带，内部 10 条短分隔线。
7. **鱼雷发射管舱门**：艇艏侧面 4 个小型圆角矩形（上下各 2），比柴电多，体现攻击核潜艇。
8. **背部导弹发射舱盖**：围壳后方 `-40 ~ -8` 一排 3 个嵌入式矩形舱盖，深色底 + 琥珀色细描边，对应 3 枚潜射导弹。
9. **围壳**：位置略靠前（`x = 14 ~ 49`），比柴电更高、更方：
   - 底边 `y = -15`，顶边 `y = -42`
   - 前缘后掠，顶部平直，后缘近垂直
   - 顶部 2 个驾驶窗 + 1 个弱琥珀色信号灯
10. **围壳舵（fairwater planes）**：从围壳前缘 `x ≈ 18, y ≈ -26` 向艇艏方向伸出到 `x ≈ 62` 的薄翼，深色填充 + 青色描边。
11. **桅杆**：2 根可升降桅杆（潜望镜 + 通信桅），高度到 `y ≈ -54`。
12. **舷号**：仅在 `this.facing === 1` 时绘制 `093A`（避免镜像文字），`8px monospace`，低透明度灰白色，位于艇体中后部。
13. **受击红闪**：由外层统一用 `nuclearHullPath` 裁剪。

不引入图片、字体或外部资源，全部 Canvas 程序化绘制。

#### 3.2.4 新增 `Missile` 类

```js
class Missile {
  constructor(x, y, game) { ... }
  update(dt, game) { ... }
  draw(ctx, time) { ... }
}
```

字段：

- `x / y`：世界坐标
- `state`：`'rising' | 'cruise' | 'lost'`
- `target`：当前锁定的 `Destroyer`
- `dead`、`t`、`trailTimer`、`angle`

更新逻辑：

1. **rising（水下上浮）**
   - `y -= CFG.MISSILE.RISE_SPEED * dt`
   - 每 0.06 秒发 1 个气泡尾迹
   - 当 `y <= CFG.SURFACE_Y` 时：
     - `y = CFG.SURFACE_Y`
     - `state = 'cruise'`
     - `target = game.nearestShip(this.x, CFG.MISSILE.LOCK_RANGE)`
     - 播放破水音效，`FX.splash()` + 青色冲击环
     - 若没有目标 → `state = 'lost'`
2. **cruise（出水巡航）**
   - 目标失效（`sinking / escaped / 已不在数组`）时重新锁定最近敌舰；仍无目标则进入 `lost`
   - 水平朝目标飞行：
     - `dx = target.x - this.x`
     - 每帧步进 `CFG.MISSILE.CRUISE_SPEED * dt`，但不得越过 `target.x`
   - 高度：
     - 距目标大于 96px：`y` 平滑趋近 `CFG.MISSILE.CRUISE_Y`
     - 距目标小于等于 96px：进入末段俯冲，`y` 平滑趋近 `CFG.SURFACE_Y - 4`
   - 每 0.045 秒发 1 个烟粒子，每 0.08 秒发 1 个火花
   - `Math.abs(dx) <= 24` 时调用 `game.missileExplode(this)`，自身 `dead = true`
3. **lost（无目标）**
   - 继续以 `LOST_CLIMB_SPEED` 爬升，`y < -60` 后 `dead = true`
   - 不爆炸，消耗的弹药不返还

绘制：

- rising：垂直弹体，小型尾焰 + 气泡
- cruise：按 `angle` 旋转的细长弹体（白灰色，深色弹头 + 尾翼），尾部 12~20px 抖动火焰、青色/橙色外发光
- lost：同巡航外形，向上爬升离场
- 由 `Game.draw()` 在舰船之后绘制，确保导弹出现在舰船上层建筑之前

### 3.3 `js/game.js` — 选艇、双武器与导弹结算

#### 3.3.2 新增方法

```js
weaponCfg() {
  return this.sub && this.sub.spec.weapon === 'missile' ? CFG.MISSILE : CFG.MINE;
}

selectSub(type) {
  if (this.state !== 'menu' || !CFG.SUBMARINES[type]) return;
  this.selectedType = type;
  this.sub = new Submarine(CFG.PLAYER.START_X, CFG.PLAYER.START_Y, type);
  Input.mx = this.sub.x;
  Input.my = this.sub.y;
  UI.setSubPick(type);
}

toMenu() {
  if (this.state !== 'gameover' && this.state !== 'victory') return;
  this.state = 'menu';
  this.level = null;
  this.minesArr = [];
  this.destroyers = [];
  this.charges = [];
  this.missiles = [];
  FX.reset();
  Input.clear();
  this.sub = new Submarine(CFG.PLAYER.START_X, CFG.PLAYER.START_Y, this.selectedType);
  Input.mx = this.sub.x;
  Input.my = this.sub.y;
  UI.showHUD(false);
  UI.showScreen('menu');
  UI.setSubPick(this.selectedType);
}

nearestShip(fromX, range) {
  let best = null;
  let bestDist = Infinity;
  for (const ship of this.destroyers) {
    if (ship.sinking || ship.escaped) continue;
    const d = Math.abs(ship.x - fromX);
    if (d <= range && d < bestDist) {
      bestDist = d;
      best = ship;
    }
  }
  return best;
}
```

#### 3.3.3 流程修改

- `init()`：`this.sub = new Submarine(START_X, START_Y, this.selectedType)`
- `startNewGame()`：同样按 `this.selectedType` 创建潜艇
- `startLevel()`：
  - 清空 `this.missiles = []`
  - `this.ammo = this.weaponCfg().MAGAZINE`
  - 调用 `UI.setAmmoSpec(this.sub.spec)` 刷新弹仓区
  - `UI.setAmmo(this.ammo, 1)`
- `fireMine()` 重命名为 `fireWeapon()`：
  - 通用检查：`state === 'playing'`、`fireCd <= 0`、`ammo > 0`
  - 扣弹、设置 `fireCd = weaponCfg().FIRE_CD`、启动回充
  - 柴电：保持现有逻辑，生成 `Mine`
  - 核潜艇：生成 `new Missile(this.sub.x, this.sub.y - 26, this)`，播放 `missile_launch`，发气泡
- `updateReload()` / `reloadRatio()`：`MAGAZINE`、`RELOAD` 全部从 `weaponCfg()` 读取
- `updatePlaying()`：
  - 每帧更新 `missiles`，移除 `dead`

  - `UI.setAmmo(...)` 替换原 `UI.setMines(...)`

- `damageShip(ship, dmg)`：
  - 伤害分改为 `CFG.SCORE.DAMAGE * dmg`（水雷 dmg=1 保持 +40，导弹 dmg=2 为 +80）

#### 3.3.4 新增 `missileExplode(missile)`

```js
missileExplode(missile) {
  if (missile.dead) return;
  missile.dead = true;
  missile.y = CFG.SURFACE_Y - 6;

  FX.explosion(missile.x, CFG.SURFACE_Y, CFG.MISSILE.BLAST_RADIUS, {
    underwater: false,
    shake: 14
  });
  AudioSys.play('missile_blast');

  const hits = this.destroyers.filter((ship) => {
    if (ship.sinking || ship.escaped) return false;
    return Utils.circleRect(
      missile.x, CFG.SURFACE_Y, CFG.MISSILE.BLAST_RADIUS,
      ship.x, ship.y, ship.len / 2, ship.beam / 2 + 6
    );
  });

  hits.forEach((ship, idx) => {
    if (idx > 0) {
      this.addScore(CFG.SCORE.EXTRA_HIT);
      FX.text(ship.x, ship.y - ship.beam - 28, `连锁 +${CFG.SCORE.EXTRA_HIT}`, CFG.COLORS.amberRGB, 15);
    }
    this.damageShip(ship, CFG.MISSILE.DAMAGE);
  });
}
```

```js
      ? '鼠标潜航 · 左键导弹 · P 暂停 · M 静音'
      : '鼠标潜航 · 左键布雷 · P 暂停 · M 静音';

  this.el['ammo-slots'].innerHTML = '';
  for (let i = 0; i < cfg.MAGAZINE; i++) {
    const slot = document.createElement('span');
    slot.className = 'mine-slot' + (spec.weapon === 'missile' ? ' missile' : '');
    this.el['ammo-slots'].appendChild(slot);
  }
  this._ammoKey = '';
}
```

- `setMines()` 重命名为 `setAmmo(count, ratio)`：
  - `ammo-count` 显示 `${count} / ${this._magMax}`
  - 槽位点亮逻辑不变
  - 缓存键字段由 `_minesKey` 改为 `_ammoKey`

#### 3.4.4 其余

- 结算界面不显示潜艇名称，避免额外信息密度。

## 4. 假设与决策

- 用户已确认：核潜艇**只有潜射导弹**，不再拥有水雷。
- 用户已确认：导弹**自动锁定最近敌舰**，命中后大范围爆炸；不做手动瞄准。
- 用户已确认：**开局菜单选一次，整局固定**；两种潜艇属性差异化，核潜艇更大更慢、受击判定更大，火力更强。
- 两种潜艇共用 3 条命、过关维修 +1、同一套关卡与计分框架；核潜艇不额外增加生命。
- 左键为通用开火键，两种潜艇无需切换武器；右键继续不使用。
- 导弹锁定距离 640px，弹仓 3 枚，回充 5 秒，伤害 2，爆炸半径 118；以上全部集中在 `CFG.MISSILE`，验证后可按手感微调。

- 核潜艇外观为"093A 特征 + 现有霓虹深海风格"：长水滴艇体、较高围壳、围壳舵、背部导弹舱盖、七叶螺旋桨、093A 舷号；不追求工程级还原。

- 只改 `config.js`、`entities.js`、`game.js`、`ui.js`、`input.js`、`audio.js`、`index.html`、`style.css`、`README.md` 与本计划文件；历史计划文档不改动。
